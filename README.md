# DSH Serverless 平台（星桥 / BridgX）

> 企业应用平台：支持私有化、云上部署和 SaaS 托管。客户可以在自己的服务器、云主机或由运营方托管的环境中部署应用，员工通过「星桥客户端」统一登录并打开应用。

- 产品名：**星桥 · BridgX**
- 控制台：**星桥控制台**
- 客户端：**星桥客户端（BridgX Client）**
- 部署形态：私有化单机、云主机/云上部署、SaaS 托管
- 出品：北京星汉未来网络科技有限公司（Galaxy-Future）

---

## 1. 这套平台能做什么

- **部署应用**：上传静态站点、Node/Python 等进程应用，或把 DSH 插件包转换成独立 Web 页面；
- **统一登录**：员工安装星桥客户端，用管理员发放的一次性激活码登记设备，之后签名登录；
- **应用入口**：登录后在「我的应用」中直接打开当天有效的应用入口；应用默认带独立 token，客户端自动携带每日入口 token，无需申请；
- **运行管理**：应用启动/停止/更新/删除、访问地址、日志、QPS / CPU / 内存；
- **基础服务**：LLM、Embedding、附件、语音识别/合成、图片识别、文档解析、网页搜索/抓取，供已部署应用调用，支持客户自配模型；
- **应用市场**：应用发布、分类、安装/卸载/重装/升级；
- **开发规范**：控制台内置 DSH 插件开发指南、应用类型识别和 AI 提示词；
- **运维保障**：平台监控、版本管理、客户端发布、本地快照备份与一键恢复；
- **部署灵活**：控制台、服务端、客户端可部署在客户内网、云主机，或由运营方以 SaaS 方式托管；备份目录可指向本地磁盘、NAS 或云盘。

> 日常操作步骤请看控制台「帮助 → 使用指南」，本文主要说明安装、部署、开通、安全和恢复。

## 2. 部署前准备

### 2.1 部署形态

| 形态 | 适用场景 | 数据与网络 |
|---|---|---|
| **私有化单机** | 客户内网、数据不出内网 | 数据在本机；备份可指 NAS/第二块盘；通过内网 IP 访问 |
| **云上部署（IaaS）** | 客户自己的云主机/VPC | 数据在云盘；建议云盘快照 + 平台快照；通过域名/反代访问 |
| **SaaS 托管** | 运营方统一托管、为客户开通使用 | 按客户隔离要求使用独立实例或独立数据目录；由运营方负责 TLS、域名、备份与升级 |

> 不同形态使用同一套控制台、客户端和部署流程，区别主要在主机、网络、域名和备份位置。SaaS 场景建议每个客户使用独立数据目录或独立实例，避免数据混用。

### 2.2 服务器

| 项目 | 要求 |
|---|---|
| 操作系统 | macOS 13+（Apple Silicon / Intel）、Windows 10/11 64 位、Linux x86_64 / arm64（需使用对应 DSH 发行版） |
| 内存 | 最低 8 GB，建议 16 GB 及以上 |
| 磁盘 | 系统盘 + 应用盘建议 50 GB 起；应用和备份占用按实际包体计算 |
| 网络 | 固定局域网 IP，例如 `192.168.1.10` |
| 浏览器 | Chrome / Edge / Safari 最新版 |

### 2.3 网络端口

- **平台访问端口：`63510`**（默认，可在配置中修改）；
- 员工电脑需要能访问服务器的 `63510` 端口；
- 防火墙/安全组放行入站 `TCP 63510`；
- 不需要把 DSH 自身的页面端口开放到局域网；
- 云上/SaaS 场景建议通过 HTTPS 域名或反向代理访问，并限制管理面来源。

### 2.4 安装包

- DSH 桌面/运行时（按服务器操作系统选择）；
- 星桥平台插件包（控制台与服务端）；
- 星桥客户端安装包从控制台「客户端下载」页获取，随服务端版本发布。

## 3. 安装与启动

> 顺序不能反：**先安装 DSH 运行时 → 再安装 DSH Serverless 插件 → 最后打开控制台**。  
> 插件是 DSH 的扩展包，不是独立安装程序；不要双击 `.tgz`，要在 DSH 的「插件」页面安装。

### 3.1 第一步：安装 DSH 运行时

按服务器/电脑的操作系统选择 DSH 官方安装包：

| 系统 | 安装方式 |
|---|---|
| macOS 13+ | 下载 `.dmg`，打开后把 DSH 拖入「应用程序」；首次启动如被拦截，在「系统设置 → 隐私与安全性」允许 |
| Windows 10/11 64 位 | 下载 `.exe` 安装包，按向导安装；首次启动允许防火墙提示 |
| Linux | **当前版本暂不官方支持**；如使用交付方提供的 Linux 发行版，按其安装说明启动 |

安装完成后：

1. 启动 DSH，完成首次初始化/登录；
2. 确认 DSH 能正常打开自己的页面；
3. 不要先把 DSH 页面端口暴露到公网；后续只开放平台访问端口 `63510`。

### 3.2 第二步：安装 DSH Serverless 插件

准备插件安装包（由平台交付方提供，文件名类似）：

```text
serverless-platform-plugin-<版本>.tgz
```

安装步骤：

1. 启动 DSH；
2. 左侧点击 **「插件」**；
3. 右上角点击 **「+ 添加插件」**；
4. 安装源选择 **「自定义地址」**；
5. 把插件 `.tgz` 的**完整本地路径**粘贴进去：
   - macOS 可在 Finder 中右键安装包 → 按住 Option →「拷贝为路径名称」；
   - Windows 可按住 Shift 右键 →「复制文件地址」；
6. 点击 **「安装」**，等待安装完成；
7. 安装完成后确认插件已启用；
8. 左侧栏出现 **「星桥控制台」**，点击打开。

如果交付方给了直链，也可以在「自定义地址」中粘贴 HTTPS 直链安装。最新版插件直链：

```text
https://gcom-aibot-assets.galaxy-future.com/dsh-serverless/plugins/serverless-platform-plugin-latest.tgz
```

> `latest.tgz` 始终指向当前最新版本；如需固定版本或离线安装，使用交付方提供的 `serverless-platform-plugin-<版本>.tgz`。

### 3.3 第三步：首次启动与访问地址

1. 打开「星桥控制台」；
2. 首次启动会自动启动平台 supervisor；
3. 默认访问地址：

```text
http://127.0.0.1:63510
```

4. 局域网访问地址通常为：

```text
http://<服务器局域网IP>:63510
```

5. 如果 63510 被占用，按平台提示修改访问端口，并同步放行防火墙。

### 3.4 macOS 网络设置

1. 打开「系统设置 → 网络/防火墙」；
2. 允许 DSH/平台进程接受局域网连接；
3. 员工电脑访问 `http://<服务器IP>:63510` 验证。

### 3.5 Windows 网络设置

1. 打开「Windows Defender 防火墙 → 高级设置」；
2. 新建入站规则，放行 `TCP 63510`；
3. 员工电脑访问 `http://<服务器IP>:63510` 验证。

### 3.6 Linux（仅交付方提供发行版时）

1. 放行防火墙 `TCP 63510`：
   - `firewalld`：`firewall-cmd --add-port=63510/tcp --permanent && firewall-cmd --reload`
   - `ufw`：`ufw allow 63510/tcp`
2. 无图形界面时，用内网浏览器访问控制台。

### 3.7 确认安装成功

打开控制台后确认：

- 顶部显示「平台正常」；
- 能看到访问地址；
- 「基础服务」能读取状态（未配置 LLM 显示不可用属正常）；
- 能新建部署并看到应用卡片；
- 左侧有「星桥控制台」，客户端下载页能生成激活码。

### 3.8 升级插件

1. 拿到新版本 `serverless-platform-plugin-<新版本>.tgz`；
2. 在 DSH「插件」页重新选择该包安装/更新；
3. 完全退出 DSH 再启动（加载新 Host 代码与 supervisor）；
4. 打开控制台确认版本号与「平台正常」；
5. 已部署应用、用户、快照和应用市场数据保留。

> 只更新客户端插件包不会自动更新服务端平台；服务端与本机 DSH 插件要使用同一版本线。

### 3.9 常见安装问题

| 现象 | 处理 |
|---|---|
| DSH 里找不到「插件」入口 | 确认 DSH 版本支持插件管理；使用完整页面而非嵌入窗口 |
| 添加插件后安装失败 | 检查路径是否为完整 `.tgz` 路径、文件是否完整、是否有读权限 |
| 安装后没有「星桥控制台」 | 确认插件已启用；完全退出 DSH 再启动 |
| 控制台打不开/端口不通 | 检查 63510 是否监听、防火墙是否放行、是否填了 DSH 页面端口而不是平台端口 |
| 员工客户端连不上 | 填 `http://<服务器IP>:63510`，不要填 DSH 页面端口；确认员工电脑能访问该 IP 和端口 |

## 4. 管理员快速开始

### 4.1 创建第一个应用

1. 打开星桥控制台；
2. 点击「新建部署」；
3. 上传应用包（`.zip` / `.tgz` / `.tar.gz`）或静态站点；
4. 等待构建完成，在应用列表看到「运行中」；
5. 点击应用卡片上的访问地址验证。

### 4.2 创建用户并生成激活码

1. 进入「客户端下载」；
2. 在「用户与激活码」中创建用户（姓名必填，邮箱可选）；
3. 选择用户，点击「生成激活码」；
4. 复制 **服务器地址** 和 **一次性激活码**，发给员工。

### 4.3 发给员工的材料

- 星桥客户端安装包（控制台「客户端下载」页）；
- 服务器地址，例如 `http://192.168.1.10:63510`；
- 一次性激活码；
- 简单说明：安装客户端 → 填服务器地址 → 粘贴激活码 → 登录。

## 5. 员工如何使用

1. 安装 DSH 与星桥客户端；
2. 打开星桥客户端，填写管理员给的服务器地址；
3. 粘贴一次性激活码，点击「激活设备」；
4. 点击「登录星桥」；
5. 在「我的应用」中点击「打开」进入应用；
6. 有新版本时，客户端会提示「发现新版本」，点「同意并更新」即可完成更新。

注意：

- 激活码一次性使用，过期或已使用需管理员重新生成；
- 设备激活后私钥保存在本机，不会上传服务器；
- 应用入口链接按天签发，第二天点击「刷新应用」获取新链接。

## 7. 数据、安全与备份恢复

### 7.1 数据保存在哪里

- 平台状态、应用文件、用户/设备、发布包都在本机数据目录；
- 备份默认保存在数据目录之外的本地备份目录，也可指向 NAS 或云盘路径；
- 私有化、云上、SaaS 三种形态的数据位置由部署方决定。

### 7.2 安全边界

- 星桥客户端私钥保存在设备本机，不上传；
- 应用默认 `tokenRequired=true`，自动生成访问 token；已登录客户端通过每日入口 token 无感访问；
- DSH 账号首次接入需管理员确认一次；账号确认后前 5 台设备自动 active，超过 5 台需管理员确认；旧设备保留 active，可手动吊销；
- 认证接口使用设备签名 + 每日客户端密钥；
- 平台管理面默认只在本机访问，通过登录插件访问应用；
- 请勿把管理端口和 DSH 页面直接暴露到公网；
- 建议通过 VPN / 内网访问，并限制 `63510` 的来源网段。

### 7.3 应用业务数据

- 转换页（reading-chat、worklog 等）的业务数据直接读写平台数据目录，不再以浏览器 IndexedDB 为主存储；
- 数据按「应用 + 用户」隔离，重启机器、换 IP、换机器后直接读平台数据；
- 旧浏览器 IndexedDB 数据会在首次打开时自动迁移到平台（优先使用平台旧备份，其次读取本机旧数据）；
- 平台 API 不可用时临时降级到本机存储，并在页面提示“当前未同步到平台”；
- 应用业务数据随平台快照一起备份和恢复。

### 7.4 自动快照与恢复

- 默认 **每小时** 自动快照一次，保留 **25 份**；
- 保留策略：近期密、远期疏，最近一天可细粒度回退，30 天后每月 1 份，覆盖约一年；
- 建议把备份目录指到 **NAS / 第二块盘**：
  - 环境变量 `SERVERLESS_BACKUP_DIR=/Volumes/backup/serverless-platform-backups`（macOS/Linux）；
  - 或在平台设置中填写相同路径；
- 恢复流程：
  1. 在「备份与恢复」选择快照；
  2. 点击恢复并确认；
  3. 平台先自动生成安全快照；
  4. 重启 DSH，启动时自动完成数据恢复；
  5. 若失败会自动回滚并保留恢复请求，可重试。

> 快照与数据在同一块磁盘时，控制台会提示风险；生产环境建议使用独立磁盘/NAS。

## 8. 常见问题

**Q：浏览器打不开控制台？**  
确认 DSH 正在运行、星桥平台插件已启用，并检查访问端口 `63510` 和防火墙。

**Q：员工客户端提示无法连接？**  
- 服务器地址填 `http://<服务器IP>:63510`，不要填 DSH 页面端口；
- 确认员工电脑能访问服务器 `63510`；
- 客户端需更新到最新版本，旧版可能不支持当前接口。

**Q：客户端登录后没有应用？**  
- 点击「刷新应用」；
- 确认管理员已部署应用并完成运行；
- 应用入口按天更新，跨天后需要刷新。

**Q：应用是 DSH 插件转换页，部分功能打不开？**  
- 转换页依赖本机 DSH 的 Host 能力；
- 确认 DSH 正在运行，并已将插件安装到 DSH；
- 新版平台会通过桥接自动恢复 book-info、语音、图片识别等能力。

**Q：恢复快照后没生效？**  
恢复是排队执行：需要重启 DSH，启动时 Host 才会替换数据。

**Q：备份可以放云盘吗？**  
可以，但需要客户自行提供可挂载的本地/内网路径。平台不强制依赖任何云服务。

**Q：升级平台会不会丢数据？**  
正常升级只更新程序，不改数据；升级前建议先手动创建一份快照。

## 9. 近期能力与开发规范

### 9.1 应用市场

- 应用可发布到应用市场，支持分类、截图、README、版本更新；
- 市场应用支持安装、卸载、重装、升级；
- 组合应用发布到市场时会带上服务、中间件、绑定、token 设置和运行说明；
- 已安装应用与市场应用在控制台区分展示，避免重复安装。

### 9.2 基础服务

- LLM、Embedding、网页搜索/抓取、文档解析、图片识别、附件、语音等由平台统一提供；
- 应用通过 `/services/<appId>/...` + service token 调用，不直接持有厂商凭据；
- 支持客户自配国内常用大模型（DeepSeek、通义千问、Kimi、智谱、豆包、MiniMax、硅基流动）、本机 Ollama 和任意 OpenAI 兼容自建服务；
- 配置卡支持图片/文档拖拽、文本粘贴，AI 抽取后填入表单；密钥只保存在 Host，只回显掩码；
- 数据库/Redis 等通过 manifest 的 `middlewares` / `bindings` 声明，连接串由平台注入，不硬编码。

### 9.3 管理员与权限

- 平台统一提供身份：`GET /__platform/identity` 返回 `user`、`roles`、`isAdmin`；
- 管理员最多 3 个，控制台可设置/取消，用户列表和客户端显示管理员标识；
- 应用只负责“管理员能看到什么、能操作什么”，不自己维护管理员名单；
- Host 管理接口必须二次校验管理员身份；普通用户隐藏入口不等于权限边界。

### 9.4 DSH 插件开发指南

控制台「应用 → DSH插件开发指南」提供完整规范、验收清单和可复制提示词：

- 先识别客户想开发的应用类型（AI/数据/媒体/运维/自动化/协作/内容/工具/其他），再生成对应提示词；
- 基础服务逐项确认：平台内置 / 外置 provider / 应用自带 / 不需要，确认后才生成提示词；
- 覆盖安装包结构、Host/Client 分层、管理员权限、数据迁移、安全、健康检查、测试和打包验收；
- 已有插件也有专门的改造提示词，要求 DSH 读取当前工作区、保留业务能力并补充兼容/回滚方案。

### 9.5 实时同步与发布历史

- 应用数据带 revision 和 SSE 变更通知，同一服务端、同一用户的多个页面/设备会同步；
- 不自动刷新页面，页面可监听 `sl-platform-data-sync` 自行更新 UI；
- 组合应用发布历史汇总当前及历史服务实例的部署记录，不再只显示一条；
- 页面入口缺失时保持 failed，不会误显示运行中；部分服务失败时页面仍可部署并标记 degraded。

## 10. 支持与反馈

- 星桥客户端版本：以客户端右上角或「客户端下载」页为准；
- DSH 版本：建议使用平台发布时标注的兼容版本；
- 平台会检查客户端最低支持版本，过低时要求更新后才能登录。

需要支持时请提供：

1. 平台版本、客户端版本、DSH 版本；
2. 服务器操作系统与访问地址；
3. 出错页面的截图或错误码；
4. 如涉及恢复，提供快照时间和恢复提示。
